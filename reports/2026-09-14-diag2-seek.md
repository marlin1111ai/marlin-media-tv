# Diagnosis 2: playback after seeking — 2026-09-14

Read-only pass. No app code, project setting, VLCKit build or Mac install was changed. The working-tree change is this report plus the evidence it cites (`reports/logs/diag2-*.log`, `reports/screenshots/diag2-*`). A temporary XCUITest harness (`DiagSeekUITests.swift`, source in Appendix A, modelled on yesterday's) drove the device and was deleted afterwards; it was never committed.

**One deviation from the brief, stated up front.** The second run per file was specified as "a single long jump (scrub to 5:00 in one seek)". The app has no scrub and no long jump: the only seeks it can issue are −10 s / +30 s while playing and the one-frame seek-back while paused (`PlayerModel.swift:227-245`, D008). A single 5-minute seek cannot be produced from the remote, and adding one would be an app change. The second run is therefore the nearest thing the remote can do: the same ten +30 s presses sent as fast as `XCUIRemote` delivers them (all ten within 2.0 s, 0.22 s apart) instead of at a user's pace (1.2 s apart). The logs show every one of the ten presses is executed as its own seek in both variants; VLC does not coalesce them. Whether a true single seek would behave like the rapid burst is in §7 as a question.

## Finding

**Named cause, with the code to match: forward seeks in this VLC build over HTTP do not use the Matroska Cues.** The default `mkv` demuxer loads every cue point as *questionable* and, because the HTTP access reports "not fast-seekable", never runs the pass that would verify them. When a seek arrives it therefore walks backwards from the target until it finds a keyframe it has already read, and decodes-and-discards ("prerolls") everything from there to the target. Consequences seen in all eight MKV runs:

- **Divergent and Wonder Woman** (HEVC in SimpleBlocks): each +30 s skip starts from the last keyframe the demuxer had reached, so ten skips in a row preroll almost the whole distance — 145 s (paced) / 276 s (rapid) of Divergent, 224 s / 289 s of Wonder Woman. The picture comes back 10 s / 20 s after the last press on Divergent and **43 s / 51 s** on Wonder Woman, during which about 2 GB is pulled from the server.
- **Stargate, both editions** (MPEG-2 in BlockGroups, from which this demuxer never learns a keyframe): every seek restarts at the **first cluster of the file** (`Range: bytes=5816-`, requested up to ten times in one run — the repeated-same-range pattern the brief asked about) and prerolls the entire 60–330 s; the picture is back 8–11 s after the last press because SD MPEG-2 prerolls at ~40× real time.
- **The MP4** (H.264, the control) seeks by its sample tables: every one of the ten presses starts 0.2–0.6 s before its target (`track[Id 0x1] using Sync Sample Box (stss)`, `seeking with 586ms preroll`), the picture is back 0.1–0.2 s after each press, and one exact-range request is made per press. No stall at all.

After the picture returns, every file plays as it did from the start in yesterday's report: no further buffering, no HTTP request, the audio output starts once and stays up, and the overlay clock advances 59 s per 59-s shot interval in all ten runs. Wonder Woman's steady 3.6 drops/s from yesterday resumes unchanged after the seek; the seek adds nothing to it. No loop was found: no range was requested twice except Stargate's file-start range (once per press, never repeating after the presses stopped), and no run re-buffered after its single post-seek fill. Audio was never lost in the logs; it could not be heard (§6).

### 1.4 HTTP during and after the seeks

MKV runs: the requests listed in §1.1, all `206 Partial Content` with exact `Content-Range`, each started at the byte of a start point above and abandoned when the next press moved the demuxer elsewhere (`connection failed` = `modules/access/http/h1conn.c:130`, the forced close of an HTTP/1 body being released). Requests per minute after resume: 0 in every run. Divergent B and Wonder Woman B issued only 2 requests for 10 seeks because the rapid presses kept the start point inside the 16 MiB read-ahead window; Stargate B/Thea B issued 3 because the window still held the head of the file. Where a start point was outside the window, one new request per press. MP4 runs: one request per press at the target's own byte offset (10 per run), none repeated, none after the last press.

Throughput implied by the prerolls (bytes between the start point and the target, divided by the stall): Divergent B ≈ 265 MB in 20 s ≈ 13 MB/s; Stargate A ≈ 240 MB in 8.5 s ≈ 28 MB/s; Wonder Woman A ≈ 1.9 GB in 43 s ≈ 45 MB/s, B ≈ 2.2 GB in 51 s ≈ 43 MB/s. So the Apple TV's path to the server carried at least 43 MB/s (≈ 350 Mbit/s) sustained; the Divergent figure is decode-bound (4K HEVC prerolling at ~14× real time), not link-bound. This tightens yesterday's "consistent with Wi-Fi" note: whatever the link is, it is not a 100 Mbit/s one.

## 4. Differential: what the logs and the files show differs

### 4.1 Demux resync and Cues use — the cause
- The demuxer loaded the Cues of every MKV at open (`|   - cues at N`, `|   + Cues`, `|   - loading cues done.` in all logs) and then did not use them for any of the 80 seeks: not one `start-pts` equals the cue just before its target.
- Code path (source of the build, `~/vlckit-build/VLCKit/libvlc/vlc/modules/demux/mkv/`):
  1. The `mkv` demux module (capability 50, the one the logs show: `using demux module "mkv"`) opens with `trust_cues = false` (`mkv.cpp:280-284`); only the capability-0 submodule `mkv_trusted` passes `true` and nothing selects it.
  2. `LoadCues` therefore files every cue point at trust level `QUESTIONABLE` (`matroska_segment.cpp:209-218`).
  3. At open the demuxer asks `STREAM_CAN_FASTSEEK` (`mkv.cpp:130-131`); the HTTP access answers `false` (`modules/access/http/access.c:79-80`) and so does the `prefetch` filter in front of it (`modules/stream_filter/prefetch.c:355-356`), so `b_fastseekable = false`.
  4. `SegmentSeeker::get_seekpoints` (`matroska_segment_seeker.cpp:296-352`) skips `index_range()` — the step that would read the clusters around the target and add `TRUSTED` keyframe seekpoints — whenever `b_fastseekable` is false (line 321).
  5. `find_greatest_seekpoints_in_range` → `get_first_seekpoint_around(target, …, TRUSTED)` (`seeker.cpp:183-207`, default trust `TRUSTED` in `matroska_segment_seeker.hpp:105`) starts at the greatest cue ≤ target and *rewinds* until it meets a `TRUSTED` seekpoint; if none, it returns the first seekpoint of the track (`return *it_begin`, line 207).
  6. `TRUSTED` seekpoints exist only for keyframes the demuxer has already read: `add_seekpoint` on `IsKeyframe()` **SimpleBlocks** (`matroska_segment.cpp:1262-1267`); a video `Block` inside a **BlockGroup** never adds one (lines 1290-1295 handle subtitle tracks only).
  7. `Seek()` then prerolls from that point (`matroska_segment.cpp:851-878`, `ES_OUT_SET_NEXT_DISPLAY_TIME` = target): every block is read and decoded and discarded until the target.
- Why the files differ: the first cluster of each MKV, fetched from the server and scanned (`cues/scan-cluster.py`, 3 MB slice each): Divergent and Wonder Woman carry video track 1 in **SimpleBlocks** (24 per cluster, 1 keyframe per 1-second cluster) → trusted keyframes accumulate as playback reads them → seek start = last keyframe read. Stargate Extended and Theatrical carry their MPEG-2 video in **BlockGroups** (12 / 15 per cluster; audio in SimpleBlocks) → no trusted video keyframe ever → `*it_begin` → the file start, every time.

### 4.3 The other candidates named in the brief
- **Cache size vs bitrate:** the 16 MiB read-ahead (`prefetch-buffer-size`) held 10.6 s of Divergent, 22.8 s of Stargate, 2.4 s of Wonder Woman. It decides only how many *requests* the burst costs (2–4 when successive start points fall inside the window, one per press otherwise); it never ran dry after resume (no `Buffering` line after the single post-seek fill in any run). Not the cause.
- **Decoder restart:** none. No `killing decoder` / `codec (…) started` / `restarting` line between Play and dismiss in any run; the VideoToolbox session survived every seek (no `restarting vt session`).
- **Audio ES re-selection:** none (§2).
- **Clock / PTS jumps:** `ES_OUT_RESET_PCR called` once per press (the normal seek reset) and nothing else: no `resetting master clock`, no `clock gap`, no `Invalid PCR delay`, no `pts_delay increased` line in any of the ten logs — unlike the paused frame-back seeks of the pass-1 report, which did loop through PCR resets. Seeks while playing do not trigger that path.
- **HTTP / server:** every request answered `206` with the exact range; no 416, no retry, no request repeated after the presses stopped. The Stargate `5816-` repeats are one request per press, each abandoned by the next press, not a loop.
- **MP4:** the `mp4` demuxer seeks with its sample tables (`track[Id 0x1] using Sync Sample Box (stss)`, `modules/demux/mp4/mp4.c:1931-1963`), which need no trust pass: the preroll is the distance to the previous sync sample (0.24–0.59 s here), one new Range request at that byte, picture back in 0.1–0.2 s. The MP4 also resumed *between* presses in the paced run (ten `buffering 1.0`, ten audio-output starts), which no MKV did.

## 5. What would confirm it, and what the evidence points at

The evidence points at **VLC's Matroska seek strategy over a non-fast-seekable stream (HTTP)**, not at the network, the server, the files' indexes, the audio path, or the app's skip arithmetic. Confirmation, none of it done here because each is a change:
1. Play the same MKVs through VLC's `mkv_trusted` demuxer (`:demux=mkv_trusted` as a media option) — if seeks then start at the cue before the target, the trust flag is the whole story. This is one option string, but it is an app change and outside this pass.
2. Play the same MKV from a local file on a Mac with the same libvlc (fast-seekable → `index_range` runs) — expected: seek lands at the cue before the target.
3. Remux Stargate with SimpleBlocks (mkvmerge default for MPEG-2 today) — expected: it would behave like Divergent (restart from the last keyframe read, not the file start).
4. A true single 5-minute seek (not reachable from the remote): expected from the code to behave like the rapid burst's last seek — one preroll from the last keyframe read (Divergent/Wonder Woman) or the file start (Stargate).

## 6. What could not be tested

- A single long jump (see the deviation note at the top): no scrub, no long-jump input exists in the app.
- Audible audio after the seek: only the audio output's log lines and the ES selection state were observable.
- Late/dropped pictures *per minute* after the seek: VLC's lines carry no timestamps and the app logs no per-minute anchor while playing; the counts above are over the whole post-resume interval (bounded by the app's stamped `buffering 1.0` and `dismiss` lines). Wonder Woman's rate is uniform across the log (200 `too late` lines per 200 lines).
- VLC's read/demux byte counters (not logged; the app does not read `libvlc_media_player_get_stats`).
- Backward skips (−10 s) and seeks while paused: outside the brief; the pass-1 report covers the paused frame-back case.
- The Apple TV's interface type: still not readable; the preroll throughput (≥ 43 MB/s) only rules out a 100 Mbit/s link.

## Appendix A — the temporary harness (deleted after the runs; not committed)

//  Plays a file for 20 s, presses the +30 s skip (right click while playing) ten times — variant A at a

//  for one long jump: the app has no scrub) — then photographs the overlay each minute for four minutes.
//  Not a standing test; not committed.

import XCTest

final class DiagSeekUITests: XCTestCase {
    private var app: XCUIApplication!
    private let remote = XCUIRemote.shared
    private let headerOrder = ["tab.Movies", "tab.TV Shows", "tab.Videos", "sort"]

    override func setUp() {
        continueAfterFailure = true
        app = XCUIApplication()
        app.launch()
        XCTAssertTrue(app.buttons["tab.Movies"].waitForExistence(timeout: 60), "library did not load")

    }

    private func shot(_ name: String) {
        let a = XCTAttachment(screenshot: XCUIScreen.main.screenshot()); a.name = name; a.lifetime = .keepAlways; add(a)
    }
    private func note(_ t: String) { let a = XCTAttachment(string: t); a.name = "note"; a.lifetime = .keepAlways; add(a); NSLog("[diag2] %@", t) }
    private func press(_ b: XCUIRemote.Button, _ n: Int = 1, wait: UInt32 = 1) { for _ in 0..<n { remote.press(b); sleep(wait) } }
    private func focusedIds() -> [String] {
        app.descendants(matching: .any).matching(NSPredicate(format: "hasFocus == YES")).allElementsBoundByIndex.map { $0.identifier.isEmpty ? "(\($0.label))" : $0.identifier }
    }
    private func isFocused(_ id: String) -> Bool { focusedIds().contains(id) }
    private func isFocused(prefix: String) -> Bool { focusedIds().contains { $0.hasPrefix(prefix) } }
    @discardableResult private func moveUntilFocused(_ id: String, pressing b: XCUIRemote.Button, limit: Int = 8) -> Bool {
        for _ in 0..<limit { if isFocused(id) { return true }; press(b) }
        return isFocused(id)
    }
    private func focusHeader() { for _ in 0..<8 { if isFocused(prefix: "tab.") || isFocused("sort") { return }; press(.up) } }
    private func focusHeaderItem(_ id: String) {
        focusHeader(); guard let target = headerOrder.firstIndex(of: id) else { return }
        for _ in 0..<8 { if isFocused(id) { return }; let cur = headerOrder.firstIndex { isFocused($0) } ?? 0; press(cur < target ? .right : .left) }
    }
    private func selectTab(_ name: String) { focusHeaderItem("tab.\(name)"); press(.select, wait: 2) }
    private func openPoster(_ id: String, tab: String) {
        selectTab(tab); press(.down); if !isFocused(prefix: "poster.") { press(.down) }
        _ = moveUntilFocused(id, pressing: .right, limit: 6) || moveUntilFocused(id, pressing: .left, limit: 6)
        press(.select, wait: 3)
        XCTAssertTrue(app.staticTexts["detail.title"].waitForExistence(timeout: 20), "detail did not open; focus \(focusedIds())")
        sleep(2)
    }
    private func pressPlay() { if !isFocused("play") { moveUntilFocused("play", pressing: .up, limit: 6) }; press(.select, wait: 2) }

    private func stamp() -> String {
        let f = DateFormatter(); f.dateFormat = "HH:mm:ss.SSS"; return f.string(from: Date())
    }

    /// 20 s from the start, then ten +30 s skips (right click while playing), then four minute-marks.
    /// `.down` is the app's "focus back on the surface" press (a no-op when focus is already there), so a
    /// `.right` afterwards is a skip and not a move between the overlay buttons.
    private func seekRun(_ tag: String, rapid: Bool) {
        XCTAssertTrue(app.otherElements["player"].waitForExistence(timeout: 20), "player did not appear; focus \(focusedIds())")
        note("\(tag): player up at \(stamp())")
        sleep(20)
        press(.down, wait: 1)
        press(.up, wait: 1); shot("seek-\(tag)-pre"); press(.down, wait: 1)
        sleep(4)
        note("\(tag): ten +30 s skips (\(rapid ? "rapid" : "paced")) begin at \(stamp())")
        for _ in 0..<10 { remote.press(.right); if !rapid { sleep(1) } }
        note("\(tag): skips end at \(stamp())")
        sleep(1); shot("seek-\(tag)-after-skips")
        note("\(tag): after-skips shot at \(stamp()), player exists \(app.otherElements["player"].exists)")
        for m in 1...4 {
            sleep(56)
            press(.up, wait: 1)
            shot("seek-\(tag)-min\(m)")
            note("\(tag): minute \(m) shot at \(stamp()), player exists \(app.otherElements["player"].exists)")
            press(.down, wait: 1)
            if !app.otherElements["player"].exists { note("\(tag): player gone at minute \(m)"); break }
        }
        press(.menu, wait: 3)
    }

    private func openStargate(_ edition: String, dir: XCUIRemote.Button) {
        openPoster("poster.Stargate", tab: "Movies"); pressPlay()
        XCTAssertTrue(app.buttons["pick.\(edition)"].waitForExistence(timeout: 5)); moveUntilFocused("pick.\(edition)", pressing: dir, limit: 3); press(.select, wait: 2)
    }
    private func openMagicians() {
        openPoster("poster.The Magicians", tab: "TV Shows")
        XCTAssertTrue(app.buttons["season.1"].waitForExistence(timeout: 30)); sleep(2)
        moveUntilFocused("episode.1.1", pressing: .down, limit: 4); press(.select, wait: 2)
    }

    func seekA_Divergent() { openPoster("poster.Divergent", tab: "Movies"); pressPlay(); seekRun("divergent-A", rapid: false) }
